你正在读的任意一篇文档

分布式系统里的共识问题，指的是一组节点在存在故障和网络延迟的前提下， 就某个值达成一致的过程。

Paxos 通过两阶段的提案与承诺机制，保证即使部分节点失联， 已经被多数派接受的值也不会被推翻。

工程实现上更常见的是 Raft，它把同样的保证拆成了领导者选举、日志复制 和安全性三个更容易讲清楚的子问题。

gpt-4o 解释 ⧉📌

这段话在说什么

  • 提案要先拿到多数节点的承诺，才允许被写入。
  • 少数节点失联不影响结论，多数派是唯一的裁判。
  • 一旦某个值被多数派接受，后续提案只能沿用它

它要什么权限，你的文字去了哪

这类工具最该讲清楚的两件事，写在这里，不藏在 FAQ 里。

为什么需要辅助功能权限

  • macOS 不允许一个应用直接读另一个应用里选中的文字
  • Omii 的做法是模拟一次 ⌘C，然后读剪贴板
  • 读完立刻把你原来的剪贴板内容写回去
  • 权限只用于这一件事，不监听按键，不截屏，不读窗口内容

不会发生的事

  • 不收集任何使用数据或遥测
  • 没有 Omii 自己的服务器，你的文字只发往你填的那个地址
  • API Key 存在 macOS 钥匙串里，日志和报错都不会打印完整 Key
  • AI 的回复内容不落盘，关掉窗口就没了

你可能会问

快捷键能改吗？

目前固定是 ⌘E。自定义快捷键在计划中。如果 ⌘E 和你常用的应用冲突，可以先在那个应用里改掉它的绑定。

支持哪些 Markdown 语法？

标题、粗体、斜体、删除线、有序与无序列表、引用、分隔线、行内代码、围栏代码块（带独立复制按钮）、Markdown 链接。表格、图片、数学公式和内嵌 HTML 暂不支持，会降级成可读的纯文本，不会显示成乱码。

为什么我的请求一直失败？

按顺序排查：Base URL 是否填对、API Key 是否还有额度、服务端是否提供 /chat/completions 接口、网络是否能直连该地址。如果你在用系统代理，Omii 会主动绕过它——因为部分代理会把 Authorization 请求头剥掉，导致鉴权失败。

钉住的窗口位置会保存吗？

不会。固定状态和窗口位置只在当前这次会话里有效，关掉浮窗或重启应用就重置了。窗口的尺寸会被记住。

可以完全离线用吗？

可以。把 Base URL 指向本机跑的 Ollama 或 LM Studio，文字就不会离开你的电脑。

为什么上不了 Mac App Store？

读取选中文字需要模拟键盘事件，这在 App Store 要求的沙盒环境里被禁止。所以 Omii 只能通过 GitHub Releases 分发。
